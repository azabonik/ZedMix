# Where the older tests went

The judge replaces Anthony's test scripts that import the editor's code (PLAN-P4b). Each section of a ported script
gets one of three dispositions:

- **judge**: a check in a judge test (named below). It observes only what a user or an AI client can see.
- **v0.2.0-only**: the literal section stays in its script, which keeps running in CI against this tree, because it
  asserts on the code's internals (a function's output, a filter-graph string, an argument list, a message text) or
  needs an operation the judge's protocol does not have yet. The reason is given.
- **drop**: removed, with the reason.

A row "judge (part)" means the section's observable outcome is judged and its internal rows stay with the script.
Checks on a hostile input crafted from the editor's saved file are recorded as not applicable, not failed, on an
editor whose file format does not hold the values as given (README "Statuses"); `judge.yml` runs with `--strict`, so
on v0.2.0 each of them must pass.
Sections are named by their number in the script (or, where it has none, their order) and what they test: the
scripts' own headings name the older code's functions, which the judge does not repeat.

## Batch 1b (graphics security)

These run on the graphics add-on (Remotion and its headless shell), which the judge installs itself and gives the
editor in `start` (README, "The graphics add-on"); without it every check on it is recorded as not applicable, and
`judge.yml` (`--strict`, with the add-on) fails that. The originals' own "skip without a cached shell" paths are gone:
the judge never skips. What the editor does is observed from outside: refusals, the State, a rendered frame's colour
(the graphic's code picks it), the rendered graphic's streams, listeners the test runs, files that appear, and every
file-system call of the editor and of everything it starts (strace; never argv).
The deferred graphics rows of batch 1a were all in `smoke-unc-e2e.ts` (sections 1, 2, 4 and 8, updated above);
`smoke-safepath.ts` has no `add_graphic` row.

## Batch 3a (edit operations)

The edits run through new operations (PROTOCOL.md: `insert_clip`, `cut_range`, `ripple_delete`, `set_track`,
`remove_track`, `link_clips`, `unlink_clip`, `set_transition`, `set_markers`, `set_speed`'s `ripple`, "Speed and time":
`set_speed_ramp`, `clear_speed_ramp`, `clear_effects`, `freeze_frame`, `reverse_clip`, `smooth_slow_motion`, and
`render_preview`), and the State gained each track's `name`, `locked`, `muted`, `hidden`, each clip's `ramp` and
`transition`, and the `markers`. The new media (`fixtures/make.sh`: `idx.mp4`, `idx2997.mp4`, `skew.mp4`, `cutout.mkv`,
`move.mp4`, `tone300.m4a`, `chirp.m4a`) show their own frame index in nine stripes and carry a chirp whose pitch says
its source moment (`chirp.m4a` is the chirp alone, a second recording), so the judge reads from an export which
source frame lands on which timeline frame and which source moment is heard there (`observe.frame_indexes`,
`observe.chirp_time`), without any model of the editor. `long.mp4` (20 s of 1080p) holds the bakes that must still
run while a test changes the timeline under them or cancels them (10 s of it each). These media are optional
fixtures: `make.sh` makes them only for a run whose tests name them (`EXTRA_MEDIA`), so the runner's self-test, whose
fixture tests use none, does not spend the time.

What the originals take from the editor's internals, and what the judge observes instead:

- **Positions.** The originals read the editor's project in memory and the edits' answers (how far later clips moved, how many,
  which linked clips changed with the clip, which clips stayed and why, which J/L-cut heads or tails were cut). The
  judge reads every position, length and speed from get_state before and after an edit and works out who moved and by
  how much itself; the answers' fields and the reasons' words stay with the scripts (protocol 1's answers carry no
  such fields, and the rewrite's answers will differ).
- **Undo.** The originals count the undo and redo stacks. The judge checks that one undo gives exactly the State from
  before the edit, and for a refusal (`edits.refused_unchanged`): just before it, a marker K is set and kept (the
  user's last edit) and a marker P is set and undone, so there is a step to redo; after the refusal the State is the
  same, redo still brings P back (an edit that had made an undo step would have dropped it), undo takes P away again,
  and the next undo takes K back (a refusal that left a step in the undo history, even an empty one, would make that
  undo do nothing visible): the undo depth and the redo history, as the user meets them. `tests/test_observe.py`
  holds the check to a model of an undo history: it passes a clean refusal and fails an empty step, a lost redo step
  and a changed State.
- **Refusals.** The originals match the error's words (the track's index and name, the clip, the fix). The judge
  checks that the editor refuses (the answer is `product_error`: a `bad_request` is the adapter's word on the
  arguments, not the editor's refusal) and that nothing changed; the wording stays with the scripts until a spec
  defines it.
- **Bakes left behind.** The originals list the editor's bake folder. The judge looks for a new media file anywhere in
  the test's folder, where the editor keeps all its files (PROTOCOL.md rule 1; `edits.left_media`: a file that starts
  like a media file, or one the judge cannot read or that is larger than 1 MiB; logs and the test's own outputs are
  left out). No render, export or preview runs between the two looks, since those write caches. A new folder, an
  empty file or a small file that does not start like media, left by a canceled or refused bake (an empty scratch
  folder, say), is not counted, though the originals' listing of the bake folder would see it: a drop. Counting new
  folders would also count the editor's caches.
- **A stopped bake.** The originals wait inside the editor's process for the bake itself to end. The judge sees only
  the answers, which may come before the work has stopped: a cancel's answer, or a job that ends in an error when a
  track is locked or the copy's spot is taken under it. So after one it leaves the clips in place (the track unlocked,
  or the spot free, again, so that a late copy could land) for one and a half times a full bake of the same media and
  2 s more, and then looks at the job, the State and the files again (`edits.stays_stopped`): a bake that went on and
  placed or kept its copy fails there. How long a full bake takes is measured in the test, just before, on a clean
  bake of another span of the same file with the same length (another span, so that an editor that keeps its copies
  cannot hand one to the bake under test). That time counts only when the clean bake did its work: when its answer
  (wait true) came, the clip plays an asset that was not there before, at the same place and timeline length
  (`edits.bake_time`). An answer that came before the copy was made would cut the hold to 2 s; the judge then knows no
  time and the check fails.
- **The limit of the hold.** A bake that went on after the answer, wrote nothing until its end and ran more than one
  and a half times as long as the clean bake timed just before it (and 2 s more) would place its copy after the
  judge's second look, and pass. A bake that writes as it goes is caught by the files check at the second look
  whatever its speed (v0.2.0's bakes do). The clean bake is timed in the same test, just before, because the same
  bake has taken up to three times as long here while other work loaded the computer.
- **What a bake holds.** The originals decode the editor's own files (a still, a reversed copy, a slow-motion copy).
  The judge reads them only through the timeline: an export, or render_frame at the still's middle.
- **The speed model.** The originals compare exported frames with the editor's own speed model (an internal
  function). The judge holds each frame to a rule a user can state (`edits.speed_rule_problems`): at constant speed s
  a clip's frame n shows a source frame inside its range, never an earlier one than frame n - 1, and the source frame
  that plays at the middle of that frame. A whole clip (placed and set to its speed as a whole, so it starts on its in
  point) is held to it exactly: in + floor((n + 1/2) * s). Where (n + 1/2) * s is a whole number (at 2x and 4x) two
  source frames meet at the middle and either may show: v0.2.0 shows the earlier one on `idx.mp4` and the later one on
  `idx2997.mp4`'s 1/30000 timebase (the original's header: FFmpeg breaks these ties by the timebase). A piece of a
  split clip may start part of a source frame into its in point, which get_state does not show, so a piece is held to
  in + n at 1x and within max(1, s / 2) source frames of in + n * s at another speed. For ramps, sync is measured by
  ear against the frames shown, and a ramp's end against its source out point.
- **The limit at a tie.** At 2x and 4x the judge cannot tell from anything a user sees which of the two frames that
  meet at a frame's middle is right: the export, a still, render_frame and the sound all agree with either. An editor
  that shows the later of the two where v0.2.0 shows the earlier (one source frame further on, consistently in its
  exports, stills and rendered frames) passes; one frame further than that fails. A one-frame shift is caught where
  there is no tie: the whole clips at 0.25x, 0.5x, 0.75x, 1x, 1.5x and 3x (test_cuts' exports, the 0.5x L-cut picture

the checks need and says its own moment where that matters (bleep.mp4's staircase: 300 + 30 k Hz in half-second steps;
onset.mkv: silence, then 440 Hz from 1 s). They are simpler than the originals' synthesis: the voice has fixed
formants (no sweep) and 24 harmonics (not 40), its floor is FFmpeg's pink noise, its "s" bursts noise high-passed at
4 kHz twice; the peaks files carry 2, 2.5 and 3 kHz tones on channel 0 instead of 220 and 330 Hz (each bucket of 1600

file's own, instead of swelling or fading over the whole file (repair round 2: see the margins). `observe.py` gained the sound measurements (README, "What is here"), and
`edits.py` the new-file check that test_colorspace had (`snapshot`, `new_file`, moved, unchanged).

Speech recognition: `bleep_words` works from the editor's word-level transcript, which only a speech model makes from
speech. The judge has no speech recording (its media are FFmpeg's tones and noise) and the editor gets no model in a
test (PROTOCOL.md rule 4: the v0.2.0 adapter names a model that does not exist, and the editor refuses to transcribe
instead of downloading one), so `get_transcript` is null and `bleep_words` must bleep nothing. The judge checks that
(refused with nothing changed, its undo history included, or no word found and nothing changed); the original's
matcher, dry run and real run seed a fake transcript into the engine's private cache, an operation no user or agent
has, so those rows stay v0.2.0-only. A check that would need the transcript is not recorded as not observed: it would
be not observed in every run, CI's `--require-trace --strict` would fail on it for good, and it would grade nothing.

installs the graphics add-on (README, "does not defend against"): an open decision.

The task text named smoke-peaks as "peaks job states, progress never backwards, cancel"; the script tests none of
